# spec/ — the vendored Comfy API v2 contract

`openapi.yaml` in this directory is a **synced, filtered copy** of the
canonical Comfy API v2 contract. It is **generated** — never hand-edit it.

## Where it comes from

The source of truth for the Comfy API v2 contract lives in a private,
internal repository maintained by the Comfy Cloud backend team; this proxy
and Comfy Cloud share the same contract so the same SDK code works against
both. Because that repo is private and this repo is public, the file never
gets copied verbatim: it is filtered first.

## What "filtered" means

Before landing here, the spec is run through `scripts/filter_openapi.py`,
which:

- Drops any operation tagged `internal` or marked `x-internal: true` (none
  exist as of this writing — every `/api/v2/*` operation is meant for
  public consumption — but the filter is there so a future internal-only
  addition, e.g. an operator/debug endpoint, can never leak here by
  accident).
- Drops any schema/parameter/response/header that only existed to support
  those internal operations (so their request/response shapes don't leak
  either).
- Replaces the source file's internal header comment (which can reference
  internal issue-tracker IDs, internal service names, and internal design
  docs) with a public-safe one.
- Redacts any internal ticket-style reference (e.g. an internal issue ID)
  that was pasted into description text upstream.
- Self-checks its own output for the same markers before writing, and
  refuses to write if any survived.

Deliberately **not** stripped: schemas that are only reachable through a
vendor extension rather than a literal `$ref` — `AssetReference` (the
`core/ASSET` object embedded in workflow JSON) and the SSE payload schemas
(`StatusEvent`, `Progress`, `PreviewEvent`, `Output`, `LogEvent`, listed
under `x-sse-events` on the events operation). These are intentionally
documentation-only in the OpenAPI sense — no operation returns them as a
literal response body — but they are very much part of the public
contract (SDK typegen and this proxy's SSE translation both depend on
them), so the filter is careful not to mistake "no direct `$ref`" for
"internal."

## One-way sync — never hand-edit

Changes flow **upstream → here only**, via a sync workflow modeled on the
same "push, filter, open a PR" pattern already used for other generated,
cross-repo artifacts derived from the same private spec. See
`docs/sync-workflow.md` for the proposed upstream-side workflow, and
`scripts/sync-spec.sh` for the script both the workflow and a human run to
actually do the filtering.

If this repo needs a contract change, it happens upstream first, then
flows down through the next sync. A PR that hand-edits `spec/openapi.yaml`
directly will be overwritten by the next sync and should not be merged as
the fix.

## Files

- `openapi.yaml` — the filtered spec. Generated; do not hand-edit.
- `VERSION` — provenance pin: which upstream commit this was synced from,
  the `info.version` at that commit, and when the sync ran. Generated by
  `scripts/sync-spec.sh`; do not hand-edit.

## Regenerating

```bash
scripts/sync-spec.sh <path-or-url-to-canonical-openapi.yaml> [source-commit-sha]
python3 scripts/generate_models.py   # regenerate the pydantic models from the new spec
```

CI (`spec-drift` job) regenerates the pydantic models from
`spec/openapi.yaml` and fails the build if the checked-in
`src/comfy_api_proxy/schemas/_generated.py` differs — that's the signal
that someone synced the spec but forgot to regenerate models, or
hand-edited the generated file.
